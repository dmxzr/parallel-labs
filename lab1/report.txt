+	Настроить рабочую среду для построения параллельных программ, реализованных при помощи стандарта OpenMP. Определить версию OpenMP, поддерживаемую используемым компилятором.

=	Исследование алгоритма
==	Описание алгоритма
Задача состоит в поиске максимального элемента в массиве A из N целых чисел.
Последовательный алгоритм работает следующим образом:
+	Инициализация: текущий максимум приравнивается минимальному возможному значению.
+	Цикл по всем элементам массива:
 -	Если массив закончился – завершаем работу
 - Сравниваем текущий элемент с сохраненным максимальным
 -	Если текущий элемент больше – обновляем максимум
 -	Переходим к следующему элементу
+	Завершение: возвращаем найденный элемент
Временная сложность: $O(N)$ – выполняется ровно N сравнений и N обращений к памяти.
 
==	Блок-схема алгоритма
#figure(

Алгоритм работает следующим образом: инициализируется текущий максимум,
затем в цикле перебираются все элементы массива, каждый сравнивается
с текущим максимумом, и при необходимости максимум обновляется. По
завершении цикла возвращается найденное значение.
 
==	Параллелизация с использованием OpenMP
Для параллелизации используются следующие директивы OpenMP:
```c
#pragma omp parallel num_threads(threads) shared(array, count) reduction(max: max) default(none) {
  #pragma omp for
  for(int i=0; i<count; i++)
  {
    if(array[i] > max) { max = array[i]; };
    }
  }
```
Особенности:
 + ```c #pragma omp parallel``` -- создает группу потоков и выполняет следующие блоки параллельно
  - ```c num_threads(threads)``` -- задает количество потоков
  - ```c shared(array, count)``` -- общие переменные для всех потоков
  - ```c redution(max: max)``` -- автоматическое объединение локальных максимумов
 + ```c #pragma omp for``` -- распределяет итерации цикла между потоками

= Теоретический анализ

== Применение закона Амдала

Для теоретической оценки предельного ускорения параллельной программы
используется закон Амдала. Он учитывает, что часть программы выполняется
последовательно и не может быть распараллелена:

$ S(p) = 1 / ((1 - alpha) + alpha / p) $

где:

- $S(p)$ --- теоретическое ускорение при использовании $p$ потоков;
- $alpha$ --- доля кода, которая может быть распараллелена;
- $(1 - alpha)$ --- доля последовательного кода.

Соответственно, теоретическая эффективность вычисляется как

$ E(p) = S(p) / p = 1 / (p (1 - alpha) + alpha) $

При стремлении $p$ к бесконечности ускорение стремится к предельному
значению $S_max = 1 / (1 - alpha)$. Именно эта величина определяет
потолок ускорения: даже при бесконечном числе потоков быстрее этого
значения программа работать не будет.

== Кусочно-аппроксимирующие модели ускорения

Классическая формула Амдала позволяет получить лишь верхнюю оценку ускорения:

$ S_A(p) = 1 / ((1 - alpha) + alpha / p) $

и не описывает фактическое поведение программы на всём диапазоне
числа потоков. Для рассматриваемой задачи экспериментальный график
ускорения имеет три качественно различных участка: рост, насыщение и
последующее падение при увеличении числа потоков.

Поэтому вместо одной кривой Амдала целесообразно использовать
кусочно-аппроксимирующую модель, в которой каждый участок описывается
отдельной теоретической зависимостью.

#figure(
  image("graph5_three_regimes.png", width: 80%),
  caption: [Экспериментальное ускорение и кусочно-аппроксимирующие теоретические кривые],
) <graph5>

=== Участок 1: $p in [1, 4]$

В области начального роста ускорение хорошо описывается моделью
насыщения:

$ S_1(p) = frac{A p}{p + B} $

с параметрами $A approx 3.25$ и $B approx 1.9$. Тогда

$ S_1(p) = frac{3.25 p}{p + 1.9}. $

Эта зависимость адекватно описывает переход от единичного ускорения к
плато. Для первого участка среднеквадратичное отклонение относительно
экспериментальных точек составляет примерно

$ text[RMSE]_1 approx 0.12. $

=== Участок 2: $p in [5, 8]$

На промежуточном участке ускорение выходит на плато и остаётся
практически постоянным. Для этого диапазона подходит зависимость вида

$ S_2(p) = 2.0 - frac{C}{p + 1}, quad C approx 0.1, $

или, в упрощённой форме,

$ S_2(p) approx 2.0. $

Это соответствует тому факту, что при $p = 5-8$ выигрыш от
дальнейшего увеличения числа потоков почти исчезает. Для второго
участка

$ text[RMSE]_2 approx 0.047. $

=== Участок 3: $p ge 9$

При больших значениях $p$ наблюдается деградация производительности.
Это связано с конкуренцией потоков за общие ресурсы, ростом накладных
расходов на синхронизацию и ограничением пропускной способности памяти.
Для этого участка удачно работает логарифмический закон:

$ S_3(p) = A - B ln p, $

где $A approx 1.7$ и $B approx 0.05$. То есть

$ S_3(p) = 1.7 - 0.05 ln p. $

Такой вид зависимости хорошо воспроизводит снижение ускорения при
переходе к большим числам потоков. Для третьего участка

$ text[RMSE]_3 approx 0.045. $

=== Итог по теоретическим кривым

Экспериментальные данные не описываются единственной кривой Амдала на
всем интервале $p$. График имеет три режима:

- на участке $[1, 4]$ --- рост и насыщение;
- на участке $[5, 8]$ --- плато;
- на участке $[9, 16]$ --- спад вследствие деградации.

Таким образом, закон Амдала следует интерпретировать не как
эталонную модель ускорения данной программы, а как верхнюю границу,
выше которой реальное ускорение не может подниматься. Для данного
эксперимента более адекватной является кусочно-аппроксимирующая
модель, которая описывает поведение графика в каждом отдельном
режиме с достаточной точностью.

  директив ```c #pragma omp parallel```, ```c #pragma omp for``` и опций
  ```c shared()```, ```c reduction()```, ```c default(none)```. Программа

  что параллельная реализация корректна и сохраняет линейную сложность
  алгоритма.

+ Измерены ускорение и эффективность параллельной программы при числе
  потоков от 1 до 16. Максимум ускорения наблюдается в диапазоне
  $p = 3-4$, после чего начинается насыщение и последующая деградация.

+ Показано, что экспериментальный график ускорения состоит из трёх
  качественно разных участков: рост, плато и спад. Это подтверждает,
  что одна кривая Амдала не описывает реальное поведение программы на
  всём диапазоне потоков.

+ Для каждого участка построена собственная теоретическая кривая:
  $S_1(p) = frac{3.25 p}{p + 1.9}$ на $p in [1, 4]$,
  $S_2(p) approx 2.0$ на $p in [5, 8]$, и
  $S_3(p) = 1.7 - 0.05 ln p$ при $p ge 9$.
  Для этих моделей получены среднеквадратичные отклонения около
  $text[RMSE]_1 approx 0.12$, $text[RMSE]_2 approx 0.047$ и
  $text[RMSE]_3 approx 0.045$ соответственно.

+ Показано, что закон Амдала следует рассматривать не как модель
  реального ускорения этой программы, а как верхнюю оценку, выше которой
  теоретически не может находиться экспериментальный график. Именно это
  и отражает результат: экспериментальные данные остаются ниже
  амдалевской верхней границы, но не повторяют её форму на всём
  диапазоне числа потоков.

*Практический вывод.* Полученные результаты показывают, что при
распараллеливании алгоритмов необходимо учитывать не только архитектуру
процессора, но и реальную структуру вычислений, накладные расходы
синхронизации и ограничение пропускной способности памяти. Для задач с
малой вычислительной интенсивностью увеличение числа потоков сверх
некоторого порога может приводить не к ускорению, а к деградации
производительности. Поэтому в данной работе более корректно говорить не
об одной кривой Амдала, а о кусочно-аппроксимирующей модели, которая
адекватно описывает три режима работы программы.
